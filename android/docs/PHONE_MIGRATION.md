# نقل المشاوير من الهاتف فقط

لديك لابتوب ويندوز؟ استخدم [أداة USB والخطوات الأبسط](WINDOWS_MIGRATION.md).

الإصدار 2.0 المنشور باسم **مشواري** يستخدم هوية `sa.rihla.next`،
فيُثبّت بجانب النسخة الأولى `sa.rihla` دون تعارض توقيع معها. هذا تثبيت مستقل:
لا يقرأ بيانات النسخة القديمة تلقائيًا ولا يحذفها. تحديث النسخة الأولى مباشرة
يتطلب مفتاح توقيعها الأصلي، وهو غير متاح في بيئة البناء الحالية. عبارة «تعارض
الحزم» ترجّح اختلاف التوقيع؛ تأكيد السبب على الهاتف يحتاج سجل التثبيت أو شهادة APK.

## استخدام النسخة الجديدة الآن

نزّل `app-v2.0-independent.apk` من مجلد `releases` وثبّته دون حذف القديم. يمكنك الدخول
مباشرة واستخدام التسجيل اليدوي، ثم إعداد المنزل والجامعة والأذونات لاحقًا.
إذا ستنقل التاريخ، نفّذ النقل قبل إنشاء مشاوير أو مصاريف أو أماكن في النسخة
الجديدة؛ الاستيراد يقبل نسخة فارغة فقط ويحمي السجلات الموجودة من الاستبدال.

## نقل محلي عبر التصحيح اللاسلكي

هذه الطريقة تستخدم الهاتف نفسه، دون كمبيوتر أو روت. تتطلب ظهور خيار
**التصحيح اللاسلكي** في خيارات المطوّر وكون التطبيق القديم نسخة اختبار تسمح
بالنسخ عبر `run-as`. النسخة الأولى التي بُنيت في هذا المشروع كانت نسخة اختبار،
لكن اتصال ADB على RedMagic الفعلي لم يُختبر هنا. إذا رفض الهاتف الإقران أو
رفض التطبيق القديم النسخ، تتوقف الأداة وتبقى بيانات القديم؛ لا تحذف التطبيق.

1. أنهِ المشوار الجاري في التطبيق القديم، وأوقف تتبعه التلقائي أثناء النقل.
2. ثبّت [Termux من F-Droid](https://f-droid.org/packages/com.termux/)، وافتحه، ثم نفّذ:

   ```sh
   pkg update
   pkg install python android-tools curl
   termux-setup-storage
   ```

   اسمح بالوصول للتخزين حتى يُحفظ الملف في «التنزيلات».

3. فعّل خيارات المطوّر من «حول الهاتف»، ثم «التصحيح اللاسلكي»، أثناء اتصال
   الهاتف بشبكة Wi-Fi. افتح الإعدادات وTermux في تقسيم الشاشة إن أمكن.
4. اختر «إقران جهاز برمز»، واستبدل `PAIR_PORT` بمنفذ الإقران الظاهر، ثم أدخل
   رمز الإقران **في Termux على هاتفك**:

   ```sh
   adb pair 127.0.0.1:PAIR_PORT
   ```

5. ارجع لشاشة التصحيح اللاسلكي الرئيسية. منفذ الاتصال فيها مختلف عن منفذ
   الإقران عادةً. استبدل `DEBUG_PORT` بذلك المنفذ:

   ```sh
   adb connect 127.0.0.1:DEBUG_PORT
   ```

   إذا لم يقبل النظام عنوان `127.0.0.1`، استخدم عنوان IP الهاتف المعروض في
   الإعدادات بدلًا منه، في الأمرين وفي `--serial` أدناه.

6. نزّل أداة النسخ ونفّذها بعد استبدال المنفذ:

   ```sh
   curl -fL https://raw.githubusercontent.com/m7mdxzx9/-/main/android/tools/prepare_legacy_backup.py -o prepare_legacy_backup.py
   python prepare_legacy_backup.py --serial 127.0.0.1:DEBUG_PORT --output /sdcard/Download/rihla-legacy.json
   ```

   الأداة توقف الكتابة في التطبيق القديم، تحفظ قاعدة البيانات وWAL والإعدادات
   الأصلية في `rihla-legacy.original.tar`، وتتحقق من سلامتها وتنتج ملف JSON
   قابلًا للاستيراد. لا تُجري إزالة تثبيت أو مسح بيانات أو إرسالًا للإنترنت.

7. افتح **مشواري 2.0 ← المزيد ← استيراد نسخة محلية**، أو اختر الاستيراد
   من شاشة الترحيب. اختر `rihla-legacy.json`، راجع أعداد المشاوير والمصاريف،
   ثم أكّد الاستيراد. تتطلب العملية بيانات جديدة فارغة، وتقبل ملفات حتى 100 MiB.
8. راجع المشاوير والمسارات والمصاريف والتعبئات والأماكن، وأعد تفعيل الأذونات
   في النسخة الجديدة. إعدادات الأذونات والتشغيل التلقائي لا تنتقل بين التطبيقين.
   أوقف التصحيح اللاسلكي بعد الانتهاء. احتفظ بالقديم حتى تتأكد من اكتمال النقل.

ملفا النسخ يحتويان مواقعك ومصاريفك؛ احتفظ بهما في مكان خاص، ولا ترفعهما إلى
GitHub. بعد مراجعة الاستيراد يمكنك نقلهما من «التنزيلات» إلى تخزين خاص.

يمكن تنفيذ الأداة نفسها من كمبيوتر لاحقًا إن لم يتوفر التصحيح اللاسلكي. أما
دون التصحيح اللاسلكي أو كمبيوتر أو مفتاح التوقيع الأصلي أو تصدير داخل النسخة
القديمة، فلا يستطيع التطبيق الجديد تجاوز عزل أندرويد لقراءة بيانات القديم.
